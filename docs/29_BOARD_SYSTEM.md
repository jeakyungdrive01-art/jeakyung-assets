# 게시판 시스템

## 목적

관리자가 업무 목적에 맞는 게시판을 생성하고 권한·표시 방식을 설정할 수 있는 게시판 빌더의 구현 기준을 정의한다.

## 게시판 설정

- 유형: 일반, 공지, 자료, 익명, Q&A, 갤러리, 프로젝트, 부서, 자유, 사용자 정의
- 테마와 목록 표시 방식
- 카테고리 사용 여부와 정렬
- 댓글·첨부파일·공지·익명 허용 여부
- 표시할 작성자 정보: 이름, 부서, 직급·직책 중 승인된 조합
- 읽기, 쓰기, 관리 권한
- Sidebar 정렬 순서
- 활성, 비활성, 보관 상태

업로드 제한과 유형별 세부 필드는 `[미정]`이며 실제 운영자 확인 후 확정한다.

## 권한 대상

- 게시판 읽기·쓰기·댓글·관리 권한은 역할, 부서, 직급·직책, 특정 사용자 대상으로 설정할 수 있어야 한다.
- 여러 대상이 겹칠 때의 우선순위와 명시적 거부 규칙은 게시판 빌더 구현 전에 확정한다.
- G2에서는 게시판 테이블과 CRUD를 만들지 않고 위 권한 모델의 확장 지점만 보존한다.

## Sidebar 그룹

1. 즐겨찾기
2. 최근 게시판
3. 전사 게시판
4. 부서 게시판
5. 프로젝트 게시판
6. 보관 게시판

- 권한이 없는 게시판은 Sidebar와 검색 결과에 표시하지 않는다.
- 직접 URL 접근도 동일한 서버 권한과 RLS로 거부한다.
- 즐겨찾기와 최근 목록은 접근 권한이 유지되는 항목만 반환한다.

## 콘텐츠 구조

- 게시글: 게시판, 카테고리, 제목, 본문, 작성자, 상태, 공지·익명 여부, 작성·수정 시각.
- 댓글: 게시글, 상위 댓글, 작성자, 본문, 상태와 시각.
- 첨부: 원본명, 저장 경로, 크기, MIME, 업로더와 검사 상태.
- 익명 글도 서버 감사 기록에서는 실제 작성자를 추적할 수 있어야 하며 일반 사용자에게 노출하지 않는다.

## 수명주기

- 삭제는 기본적으로 소프트 삭제한다.
- 게시판 비활성화 후 새 글 작성을 막고 읽기 정책을 유지한다.
- 보관 게시판은 이력을 유지하되 일반 내비게이션에서 분리한다.
- 최종 삭제는 관련 글·댓글·첨부·감사 이력을 확인하고 관리자 서버 함수에서만 검토한다.
