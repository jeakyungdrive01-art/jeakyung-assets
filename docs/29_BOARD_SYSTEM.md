# 게시판 시스템

## 목적

관리자가 업무 목적에 맞는 게시판을 생성하고 권한·표시 방식을 설정할 수 있는 게시판 빌더의 구현 기준을 정의한다.

## 게시판 설정

- 유형: 일반, 공지, 자료, 익명, Q&A, 갤러리, 프로젝트, 부서, 자유, 사용자 정의
- 테마와 목록 표시 방식
- 카테고리 사용 여부와 정렬
- 댓글·첨부파일·공지·익명 허용 여부
- 표시할 작성자 정보: 이름, 부서, 직급·직책 중 승인된 조합
- 읽기, 쓰기, 관리 권한
- Sidebar 정렬 순서
- 활성, 비활성, 보관 상태

기본 업로드 한도는 게시판별 20MB 이하로 설정하며, 비공개 `groupware-board-attachments` 버킷과 권한 확인 후 발급하는 signed URL을 사용한다. 실행 파일 계열 확장자는 기본 차단한다.

## 권한 대상

- 게시판 읽기·쓰기·댓글·관리 권한은 역할, 부서, 직급·직책, 특정 사용자 대상으로 설정할 수 있어야 한다.
- 기본은 거부이며 명시적 `allow`가 있어야 허용한다. 같은 사용자가 여러 조건에 해당하면 하나의 `deny`가 모든 `allow`보다 우선한다.
- action은 Sidebar, 목록·상세, 본인·타인 글/댓글, 첨부, 공지·고정, 카테고리·권한·설정·보관·삭제 단위로 분리한다.

## Sidebar 그룹

1. 즐겨찾기
2. 최근 게시판
3. 전사 게시판
4. 부서 게시판
5. 프로젝트 게시판
6. 보관 게시판

- 권한이 없는 게시판은 Sidebar와 검색 결과에 표시하지 않는다.
- 직접 URL 접근도 동일한 서버 권한과 RLS로 거부한다.
- 즐겨찾기와 최근 목록은 접근 권한이 유지되는 항목만 반환한다.

## 콘텐츠 구조

- 게시글: 게시판, 카테고리, 제목, 본문, 작성자, 상태, 공지·익명 여부, 작성·수정 시각.
- 댓글: 게시글, 상위 댓글, 작성자, 본문, 상태와 시각.
- 첨부: 원본명, 저장 경로, 크기, MIME, 업로더와 검사 상태.
- 익명 글도 서버 감사 기록에서는 실제 작성자를 추적할 수 있어야 하며 일반 사용자에게 노출하지 않는다.

## 수명주기

- 삭제는 기본적으로 소프트 삭제한다.
- 게시판 비활성화 후 새 글 작성을 막고 읽기 정책을 유지한다.
- 보관 게시판은 이력을 유지하되 일반 내비게이션에서 분리한다.
- 최종 삭제는 관련 글·댓글·첨부·감사 이력을 확인하고 관리자 서버 함수에서만 검토한다.

논리 테이블은 [`30_DATABASE_SCHEMA.md`](30_DATABASE_SCHEMA.md), 권한은 [`28_ROLE_AND_PERMISSION_MATRIX.md`](28_ROLE_AND_PERMISSION_MATRIX.md)를 따른다.

## G3 구현 상태

- DB 기반 10종 공통 게시판 엔진과 그룹·카테고리·관리자·권한 규칙을 구현했다.
- 사용자 화면은 즐겨찾기·최근 방문, 검색·카테고리·페이지 이동, 글 작성·임시저장·수정·소프트 삭제, 댓글·대댓글, 익명, 반응, 첨부 업로드·다운로드를 제공한다.
- 동적 Sidebar와 직접 URL은 같은 DB 권한 함수 결과를 사용하며 비활성·보관·권한 없음 상태를 숨긴다.
- 관리자 빌더는 게시판 생성·수정·복제, 활성·보관·복원, 안전 삭제, 카테고리, 관리자, 세부 allow/deny와 사용자별 권한 미리보기를 제공한다.
