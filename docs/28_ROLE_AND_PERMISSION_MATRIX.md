# 역할과 권한 매트릭스

## 역할

1. `super_admin` — 최고 관리자
2. `admin` — 관리자
3. `department_head` — 부서장
4. `team_lead` — 팀장
5. `employee` — 직원

역할은 직급·직책과 별개다. 한 사용자의 최종 권한은 역할, 소속 조직, 리소스별 정책과 명시적 예외를 서버에서 조합해 판정한다.

## 판정 원칙

- 메뉴를 숨기는 것은 편의 기능이며 보안이 아니다.
- 클라이언트, 서버 함수와 Supabase RLS가 동일한 권한 개념을 사용한다.
- 기본값은 거부이며 명시적으로 허용된 작업만 수행한다.
- 최고 관리자 권한 부여·회수, 최종 삭제와 권한 변경은 재인증과 감사 로그를 요구한다.
- 한 사용자는 여러 역할을 가질 수 있으며 `user_role_assignments`의 `(user_id, role_code)`를 유일하게 유지한다.
- 일반 관리자는 `admin`, `super_admin`을 부여할 수 없고 최고 관리자만 관리자 계열 역할을 부여한다.
- 기본 역할을 자동 부여하지 않으며 첫 최고 관리자는 별도 1회성 SQL로만 부트스트랩한다.
- 관리자 메뉴는 Auth Context의 DB 역할로 표시하고 직접 URL은 관리자 Route와 RLS·RPC가 다시 차단한다.
