# 관리자 시스템

## 관리 영역

- 회원 승인·거절과 대기 목록
- 계정 잠금·해제, 비활성화와 보관
- 부서·직급·직책과 구성원 배정·이동
- 역할·권한 관리
- 게시판 생성·설정·보관
- 시스템 설정
- 감사 로그와 로그인 기록

## 부서 수명주기

부서 삭제 요청은 다음 순서를 강제한다.

1. 비활성화
2. 소속 직원 이동
3. 게시판·결재·일정·파일·감사 이력 사용 여부 확인
4. 이력이 있으면 보관
5. 이력이 없는 경우에만 최종 삭제 검토

최종 삭제는 서버 함수, 재인증, 사유 입력과 감사 로그가 필요하다.

## 회원 승인

- 신청 정보와 회사 이메일을 확인한다.
- 승인 시 부서, 직급·직책과 최소 역할을 명시한다.
- 거절·잠금·해제·퇴사 처리에는 사유를 기록한다.
- 관리자 자신에 대한 고위험 권한 변경과 마지막 최고 관리자 제거를 방지한다.

## 감사 기준

- 대상, 작업, 이전·이후 값의 안전한 요약, 사유, 작업자와 시각을 기록한다.
- 비밀번호, 토큰과 민감한 본문은 감사 로그에 남기지 않는다.
- 감사 로그 조회 권한과 보유 기간은 `[미정]`이다.

## G2 화면

- pending 회원 목록과 신청 상세를 조회한다.
- 관리자가 최종 부서·직급·직책과 대표 역할을 선택하고 RPC로 승인한다.
- 거절 사유를 필수로 받아 RPC로 거절하며 결과를 즉시 목록에 반영한다.
- 부서·직급·직책은 생성, 이름·코드·순서 수정과 활성·비활성만 제공하고 삭제는 제공하지 않는다.
- 일반 관리자의 관리자 계열 역할 부여는 서버 함수에서 거부한다.

## 첫 최고 관리자

자동 승격은 금지한다. 정상 가입 후 `supabase/snippets/bootstrap_super_admin.sql`의 이메일 placeholder를 SQL Editor에서 일회성으로 바꿔 실행하며 승인·역할 부여·감사 로그를 한 트랜잭션에서 기록한다. 이 절차는 Data API나 브라우저 RPC로 노출하지 않는다.

## G3 구성 화면

- 대시보드 위젯: 유형·문구·이동 경로·크기·정렬·활성·필수·사용자 숨김/정렬 허용·보관과 역할/조직/사용자별 allow·deny 배포를 관리한다.
- 게시판 빌더: 그룹, 10개 유형, Sidebar·댓글·대댓글·첨부·익명·반응·검색 설정, 카테고리, 게시판 관리자와 action별 권한 규칙을 관리한다.
- 위험한 전체 관리 권한은 저장 전 별도 확인하며, 특정 사용자 기준 권한 미리보기로 서버 판정 결과를 확인한다.
- 사용 이력이 있는 위젯·게시판의 안전 삭제 요청은 보관으로 전환하고, 사용 이력이 없을 때만 물리 삭제한다.
