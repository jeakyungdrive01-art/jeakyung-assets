# 인증과 회원 관리

## 원칙

- 그룹웨어는 재경닷컴 임직원 전용이다.
- Supabase Auth는 향후 연결하며 G0–G1에서는 네트워크 인증 요청을 보내지 않는다.
- 비로그인 사용자는 보호 경로와 내부 데이터를 사용할 수 없다.
- 인증 여부와 회원 상태를 모두 통과해야 하며 UI 표시만으로 권한을 판정하지 않는다.

## 회원 상태

| 상태 | 의미 | 내부 접근 |
| --- | --- | --- |
| `pending` | 가입 신청 후 관리자 검토 전 | 금지 |
| `active` | 승인되고 사용 가능한 계정 | 역할·권한에 따라 허용 |
| `rejected` | 가입 신청 거절 | 금지 |
| `locked` | 보안 또는 관리자 조치로 잠김 | 금지 |
| `inactive` | 퇴사·휴직·탈퇴 등으로 비활성 | 금지 |
| `archived` | 이력 보존 대상 계정 | 금지 |

## 지원 기능

- 로그인·로그아웃
- 가입 신청, 관리자 승인·거절, 승인 대기
- 비밀번호 재설정·변경
- 마이페이지와 프로필 수정
- 계정 잠금·해제
- 퇴사·탈퇴의 비활성화와 보관
- 로그인 성공·실패·로그아웃 기록

## 가입 데이터

- 이름, 회사 이메일, 연락처, 부서, 직급·직책을 신청 정보로 받는다.
- 비밀번호는 Supabase Auth에만 전달하며 애플리케이션 테이블이나 로그에 저장하지 않는다.
- 회사 이메일 허용 도메인, 중복 신청, 연락처 보유 기간은 `[미정]`이다.

## G0–G1 구현 경계

- 인증 폼과 접근 가능한 상태 메시지만 구현한다.
- `localStorage`, 쿠키 또는 고정 사용자로 로그인 성공을 가장하지 않는다.
- 보호 경로는 로그인으로 이동하며 원래 경로는 라우터 상태에만 둔다.
- 향후 `AuthProvider`가 세션, 프로필과 회원 상태를 제공할 위치를 분리한다.

보안 판정과 RLS는 [`31_SECURITY_AND_RLS.md`](31_SECURITY_AND_RLS.md), 관리자 조치는 [`32_ADMIN_SYSTEM.md`](32_ADMIN_SYSTEM.md)를 따른다.
